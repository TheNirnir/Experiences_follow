# מעקב התנסויות צוות

אפליקציית ווב פשוטה עם שני דפים (מעבר ביניהם בסרגל התחתון):

- **מטלות** (הדף הראשון שנפתח): מה צריך להגיש, תג"ב, ואיפה מגישים (קמפוס / דרייב / כתב יד / אחר, אפשר כמה). רואים מי הגיש ומי עדיין לא.
  - במטלה שמוגשת **בדרייב**: בוחרים שם, מעלים PDF, והקובץ נשמר בתיקייה בשם המטלה בתוך התיקייה **"הגשות מטלות"**, שהסקריפט יוצר בעצמו. העלאה חוזרת מחליפה את הקובץ הקודם (הישן עובר לפח).
  - במטלה בלי דרייב: לוחצים על השם כדי לסמן שהגיש.
- **התנסויות**: מעקב אחרי התנסויות הדרכתיות ופיקודיות לפי שלבי מעגל החניכה.

- **האתר** (`index.html`, `config.js`) הוא דף סטטי. אפשר להעלות אותו ל-GitHub Pages.
- **הנתונים** נשמרים בגיליון Google, דרך API קטן ב-Apps Script (`Code.gs`).

כל עוד `API_URL` ב-`config.js` ריק, האתר רץ **במצב הדגמה**: הנתונים נשמרים רק בדפדפן הנוכחי.

## 1. חיבור לגיליון Google (פעם אחת)

1. פתחו גיליון חדש: [sheets.new](https://sheets.new).
2. בתפריט: **תוספים ← Apps Script**.
3. החליפו את תוכן `Code.gs` בעורך בתוכן הקובץ `Code.gs` מכאן, ושמרו.
4. בחרו את הפונקציה `setup` ולחצו **Run**. אשרו את ההרשאות (Advanced ← Go to … ← Allow).
   בגיליון ייווצרו הלשוניות **אנשים**, **שלבים**, **התנסויות**.
5. **Deploy ← New deployment**, סוג **Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
6. העתיקו את הקישור (נגמר ב-`/exec`) והדביקו אותו ב-`config.js`:
   ```js
   window.CONFIG = { API_URL: 'https://script.google.com/macros/s/XXXX/exec' };
   ```

## 2. העלאה ל-GitHub Pages

```bash
git init
git add index.html config.js Code.gs appsscript.json README.md
git commit -m "Experience tracker"
git branch -M main
git remote add origin https://github.com/<user>/<repo>.git
git push -u origin main
```

ב-GitHub: **Settings ← Pages ← Source: Deploy from a branch ← main / root ← Save**.
אחרי כדקה האתר יהיה זמין בכתובת `https://<user>.github.io/<repo>/`. בטלפון אפשר לבחור "הוספה למסך הבית".

> כל מי שיש לו את הקישור יכול לצפות ולערוך.

## רשימת ההתנסויות וקבצי ההורדה

- `catalog.js`: רשימת ההתנסויות הקבועות שמופיעות לבחירה בהוספה, עם סוג וקובץ הורדה. אפשר גם לבחור "אחר" ולכתוב שם חופשי, ואז אין קובץ.
- `files/`: קובצי ההורדה. כדי להוסיף התנסות: שמים קובץ ב-`files/`, מוסיפים שורה ב-`catalog.js` ודוחפים לגיט.
- כפתור "הורדת התנסות" מופיע בכרטיס כששם ההתנסות זהה לשם ברשימה.

## עריכת שמות, שלבים והודעות

הכול נערך ישירות בגיליון:

- **אנשים**: שם אחד בכל שורה.
- **שלבים**: `סוג | מספר | שם שלב | הודעה`. הסוג הוא `הדרכתית` או `פיקודית`, ולכל סוג יכול להיות מספר שלבים אחר.
  בהודעה אפשר לכתוב `{שם}` ו-`{התנסות}`, והם יוחלפו אוטומטית בשם החניך ובתיאור ההתנסות.
- **התנסויות**: נכתבת על ידי האפליקציה.
- **מטלות**: `id | שם | תג"ב | מקומות | אחר | תיקייה | נוצר`. נכתבת מהאפליקציה (הוספה / עריכה / מחיקה). `תיקייה` הוא מזהה תת-התיקייה בדרייב.
- **הגשות**: שורה לכל מי שהגיש מטלה (`upload` = הועלה לדרייב, `manual` = סומן ידנית), כולל קישור לקובץ.

## עדכון קוד ה-API

אחרי שינוי ב-`Code.gs`: **Deploy ← Manage deployments ← ✏️ ← Version: New version ← Deploy**. הקישור נשאר אותו קישור.

### הרשאת דרייב (פעם אחת, בגלל המטלות)

1. העתיקו את `Code.gs` **וגם** את `appsscript.json` לעורך (כדי לראות את `appsscript.json`: ⚙️ Project Settings ← "Show appsscript.json manifest file in editor").
2. הריצו את `setup` ואשרו את ההרשאות. הסקריפט מבקש רק `drive.file`: גישה **רק לקבצים שהוא עצמו יוצר**, לא לשאר הדרייב.
   ייווצרו הלשוניות **מטלות**, **הגשות** ו-**הגדרות**, ובדרייב תיווצר התיקייה **"הגשות מטלות"** (הקישור אליה מופיע בלשונית "הגדרות" ובאתר).
3. פרסמו גרסה חדשה כמו למעלה.
4. אפשר לשתף את התיקייה "הגשות מטלות" עם מי שצריך לראות את ההגשות.

בגלל ההרשאה המצומצמת הסקריפט לא יכול לעבוד עם תיקייה שקיימת מראש, רק עם תיקייה שהוא יצר. אם מוחקים את התיקייה, תיווצר תיקייה חדשה בהעלאה הבאה. גודל קובץ מקסימלי: 20MB.
